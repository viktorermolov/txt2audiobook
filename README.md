# txt2audiobook

Локальный сервис для Raspberry Pi 4: получает русскую книгу через Telegram,
озвучивает её Silero TTS на CPU и публикует один M4B в Audiobookshelf. Облако
для синтеза и GPU не нужны.

Проверено на Pi 21 сентября 2026 года: 93 автоматических теста, затем повторные
12 тестов интерфейса после последней правки команд. Автономная проверка настоящего
Silero/ffmpeg дала один M4B, две главы, 11.038 секунды и ноль пропущенных фрагментов.
Полный роман и субъективное сравнение голосов в этой проверке не использовались.

Проверено на Pi 17 сентября 2026 года: 60 автоматических тестов и сквозная
обработка FB2 через Telegram, Silero и ffmpeg до Audiobookshelf. Тест использует
синтетический входящий Update, но настоящую загрузку/скачивание Telegram и
доставку уведомления. Получен один M4B с двумя главами, серией и номером.
Отдельно проверены HTTPS-вход, защищённое аудио, Range-запросы и WebSocket.
Тестовая книга удалена через настоящий веб-интерфейс с удалением файлов:
её каталог исчезает, API возвращает 404.

## Как это работает

1. Отправьте в Telegram TXT, EPUB, FB2, RTF, HTML или Markdown.
   Автоматические уведомления: приём книги, завершение со ссылкой и ошибки.
   Этапы обработки и прогресс доступны по `/status`, без промежуточных сообщений.
   Повторные ошибки одной незавершённой публикации не рассылаются; текущая причина
   сохраняется в статусе задачи. Перезапуск сервиса также не создаёт уведомления.
2. При желании добавьте к сообщению подпись:

   ```text
   Автор: Иван Петров
   Название: Книга
   Серия: Цикл
   Номер: 02
   ```

   Подпись имеет приоритет над метаданными файла. Для FB2/EPUB извлекаются
   автор, название и, когда они присутствуют, серия и номер. Обычный TXT не
   получает выдуманную серию.
   Встроенная обложка EPUB 2/3 или FB2 автоматически переносится в Audiobookshelf
   и в сам M4B. Используется только явно указанная в книге обложка, без поиска
   в интернете. JPEG/PNG/WebP/GIF преобразуются в JPEG до 1600 пикселей по длинной
   стороне; прозрачность заменяется белым фоном, метаданные изображения удаляются.
   Отсутствующая, повреждённая обложка или изображение свыше 16 МиБ/24 мегапикселей
   пропускается без остановки озвучки. Эти ограничения не относятся к тексту или
   аудиофайлу. Ранее завершённые книги автоматически не переиздаются.
3. Файл сначала копируется в `data/work/<id>/source.*` на стадии `ingesting`,
   затем ставится в одну общую очередь. Это защищает исходник от исчезновения
   во время обработки и дедуплицирует активные одинаковые файлы по SHA-256.
4. Последовательность `extract -> clean -> synth -> assemble` создаёт один
   M4B. В рабочем пути `max_part_mib=None`, поэтому лимита размера выхода и
   разбиения под Telegram нет.
5. Публикация создаёт каталог библиотеки
   `Автор/Серия/Номер - Название [первые-12-символов-SHA256-id-задачи]/` либо
   `Автор/Название [первые-12-символов-SHA256-id-задачи]/`. В нём находятся
   `01.m4b`, `metadata.opf`, необязательная `cover.jpg` и служебная квитанция. Пара хеш/ID отличает
   повторно озвученные редакции и делает повтор публикации детерминированным.
6. Audiobookshelf обнаруживает каталог встроенным watcher; его нативное
   сканирование по cron выполняется каждые две минуты. Сервис только ждёт API
   подтверждение индексирования всех аудиофайлов с ненулевой длительностью, не
   вызывает `POST` scan. Только после этого Telegram получает HTTPS URL книги.

Кэш синтеза содержит manifest с планом и параметрами голоса. Несовпадение или
отсутствие manifest не позволяет повторно использовать старые WAV-фрагменты.
Прерванная конвертация возобновляется из сохранённых артефактов; готовая, но
не опубликованная книга остаётся в `ready`. Следующая попытка разрешается через
120 секунд после завершения предыдущей; готовые книги обслуживаются по очереди.
`/publish` запускает тот же повтор вручную и сообщает результат. Завершённые
задачи не публикуются повторно, даже если локальная квитанция утрачена.

Telegram не даёт гарантии exactly-once для финального уведомления: сбой между
подтверждением API Telegram и записью локального маркера может привести к
повторному сообщению после перезапуска. Публикация файлов защищена квитанцией,
SHA-256 каждого опубликованного аудио и атомарным переименованием, но это не
меняет семантику внешнего API.

## Команды Telegram

| Команда | Действие |
| --- | --- |
| `/status` | текущая работа, очередь и ожидающие публикации книги |
| `/queue [страница] [статус]` | история задач с фильтром, страницами и кнопками |
| `/cancel [id]` | запросить отмену активной или ожидающей конвертации |
| `/retry [id]` | запросить повтор конвертации; без ID выбирается только ошибка |
| `/publish [id]` | повторить публикацию готовой книги |
| `/resend [id]` | алиас `/publish` |
| `/restore id` | явно восстановить завершённую книгу в библиотеке |
| `/voice` | показать текущие параметры озвучки без их изменения |
| `/library` | открыть публичный URL Audiobookshelf |

Меню команд регистрируется только для личного чата владельца. Сообщения и
callback-кнопки доступны только `telegram.allowed_user_id` в его private-чате.
Отмена, повтор и восстановление требуют одноразового подтверждения, которое
истекает через две минуты. После рестарта подтверждение недействительно;
перед действием проверяется актуальное состояние задачи. Публикация не отменяется
на середине атомарного переноса файлов.

После удаления через Audiobookshelf исходный M4B конвертера остаётся в
`data/audiobook/`. Он не возвращается в библиотеку автоматически. `/restore id`
восстанавливает его только после явного подтверждения; неудачный согласованный
повтор затем может продолжаться автоматически. Исходные тексты при этом не удаляются.
Библиотека получает жёсткую ссылку на этот M4B, поэтому удаление книги
в веб-интерфейсе место на диске не освобождает: оно занято, пока жив файл
в `data/audiobook/<id>/`. Удаляйте его вручную, если `/restore` больше не нужен.

## Качество текста и звука

Короткие содержательные разделы EPUB сохраняются; навигационные и явно
нелинейные документы не читаются как обычные главы. Inline-разметка HTML не
разрывает слова, значимые степени и индексы сохраняются. Нормализация дат,
единиц и порядковых числительных проверяется русскими регрессионными примерами;
это не универсальный морфологический анализатор.

Перед сохранением звука проверяются конечность отсчётов, минимальная длительность
и наличие сигнала. Беззвучный повреждённый кэш повторно озвучивается, а намеренные
паузы из журнала `silenced.json` сохраняются. Изолированные сбои по-прежнему не
обрушивают многочасовую книгу: о пропусках сообщается и отдельно, и в финальном
уведомлении. Массовые сбои прекращают сборку. План и голосовые параметры в manifest
по-прежнему должны совпадать; начатые книги сохраняют прежний план текста.

Модель остаётся `v5_5_ru`, голос `eugene`, 48 кГц и AAC mono 64 kbit/s. Смена
PyTorch, нормализация громкости, словарь произношения, предпрослушивание и изменение
пауз требуют отдельной проверки на Pi и сравнительного прослушивания. Они не
включаются неявно вместе с исправлениями текста и меню.

## Развёртывание на Pi

Команды ниже выполняются на Pi в каталоге проекта (например,
`/opt/txt2audiobook`); локальная машина не заменяет ARM64-образ с torch и ffmpeg.

Подготовьте `data/config/config.yaml` из `config.example.yaml`. В нём хранятся
токен Telegram, разрешённый пользователь и после инициализации токен
Audiobookshelf. Настоящие секреты находятся только на Pi:

- `data/config/config.yaml` — токены Telegram и publisher API;
- `data/abs-admin/credentials.json` — учётные данные администратора ABS;
- `data/cloudflared/tunnel-token` — токен Cloudflare Tunnel, вне контейнера бота;
- `data/abs/config/absdatabase.sqlite` — содержит ключ подписи и сессии ABS.

Не добавляйте эти файлы в Git и не выводите их содержимое в логи. Резервные
копии данных размещайте в `data/backups`.

Audiobookshelf использует локальный образ `local/audiobookshelf-hardened:2.37.0`
на основе закреплённых digest upstream и Node.js 24 с обновлёнными совместимыми
зависимостями из `deploy/audiobookshelf/package-lock.json`. Сборка проверяет
фактические версии зависимостей, загружаемые Socket.IO/Engine.IO, и работу
нативного SQLite с расширением nusqlite. С 2.37.0 сервер ABS компилируется из
TypeScript: точка входа — `dist-server/index.js` (в Dockerfile и
`docker-compose.yml`). Runtime-зависимости 2.37.0 совпадают с 2.36.1, поэтому
закреплённые исправленные версии пакетов перенесены без изменений.
Библиотека доступна ABS **на запись**, чтобы удаление через веб-интерфейс
удаляло файлы. При монтировании только для чтения сканер возвращал удалённые
записи. Бот не публикует завершённые задачи повторно автоматически.
Publisher API использует обычного
неадминистративного пользователя с доступом только к библиотеке: у него нет
прав администратора и он не запрашивает сканирование. Одноразовая
инициализация создаёт библиотеку, такого пользователя и API-токен. Учётные
данные администратора монтируются только для этой команды, вне bot mount:

```bash
docker compose up -d audiobookshelf
docker compose run --rm -v "$(pwd)/data/abs-admin:/admin" \
  -v "$(pwd)/data/config:/bootstrap-config" audiobook \
  python -m scripts.bootstrap_abs --public-url https://abs.example.com --admin-user <имя>
```

`--admin-user` задаёт имя администратора ABS только при первой инициализации
(по умолчанию `admin`; лучше выбрать неочевидное), пароль генерируется случайно
и сохраняется в `data/abs-admin/credentials.json`. `--public-url` записывается
в `audiobookshelf.public_url`; без него сохраняется уже заданный адрес.

`Dockerfile` копирует `scripts/` в образ, поэтому после сборки команда доступна
в `claude-audiobook:latest` без монтирования исходного кода.

Публичный адрес задаётся `audiobookshelf.public_url` в `config.yaml`. Tunnel
выключен по умолчанию и включается отдельным профилем; используется
`cloudflare/cloudflared:2026.9.1`, токен лежит в `data/cloudflared/tunnel-token`:

```bash
docker compose --profile tunnel up -d
```

Перед пересылкой проекта не используйте `rsync --delete` против каталога с
`data/`: он содержит состояние, библиотеку и секреты. Исключайте `data/`:

```bash
rsync -az --exclude data --exclude .git --exclude __pycache__ \
  ./ pi:/opt/txt2audiobook/
```

Старые файлы из прежней папки `data/audiobook/` не импортируются в библиотеку
автоматически. После проверки резервной копии их можно удалить вручную.

## Защита

Контейнеры конвертера и ABS запускаются не от root (UID/GID 1002 по умолчанию),
с read-only корневой файловой системой, без Linux capabilities. Бот получает
только свой конфигурационный файл на чтение. Приватные каталоги имеют права
0700, файлы с данными и секретами 0600; резервные копии защищены так же.
На Cloudflare для домена библиотеки заголовок `x-client-ip` принудительно равен
проверенному `ip.src`: произвольный заголовок клиента не обходит лимит входа.
Определение правила сохранено в `deploy/cloudflare-request-header-rule.json`
(замените в нём `abs.example.com` на свой домен); оно добавляется в фазу `http_request_late_transform` без замены других правил зоны.

Модель Silero проверяется по закреплённой SHA-256 до загрузки исполняемого
пакета. Второй процесс блокируется до восстановления очереди. Готовые файлы
и записи публикации синхронизируются с диском перед подтверждением.
Новых квот или резервирования диска нет; размер итогового M4B не ограничен.
Ранее существовавший лимит исходника 200 МиБ сохранён. Защита EPUB допускает
до 1 ГиБ распакованных данных, 512 МиБ на элемент и 100 000 элементов;
аномальное сжатие (более 200:1) отклоняется для отдельного элемента крупнее
16 МиБ и для архива целиком крупнее 256 МиБ: каждый XHTML разбирается в памяти
целиком, а текст настоящей книги сжимается лишь в 3–8 раз. Это отдельные
ограничения входного архива, не размера аудиокниги.

Проверка кандидата ABS от 21 сентября 2026: Node.js 24.21.0, SQLite/nusqlite,
вход, индексирование M4B и физическое удаление библиотечных файлов работают
в отдельном контейнере с UID 1002 и read-only корнем. `npm audit --omit=dev`
сократился с 27 до 11 записей по пакетам (1 critical, 6 high, 2 moderate, 2 low);
в 2.37.0 дополнительно подняты `moment` до 2.31.0 (CVE-2026-17495) и
`proxy-addr` до 2.0.8 (подмена IP через IPv4-mapped IPv6).
Это не утверждение об отсутствии уязвимостей. Axios 0.27.2 и Nodemailer 6.10.1
требуют отдельной проверки совместимости перед major-обновлениями. Critical
для `tar` относится к инструментам установки SQLite: установка скриптов отключена,
N-API binary берётся из закреплённого upstream, но сами зависимости остаются
в образе. Также остаётся транзитивный `uuid` через Sequelize. Пакеты Alpine
берутся из репозитория при сборке; полной побитовой воспроизводимости образа нет.
Не используйте `npm audit fix --force` без проверки поведения ABS.

Для уже существующей установки `scripts/harden_data.py` выполняется от root
**только при остановленных контейнерах проекта**. Он сохраняет резервную
копию, переносит токен туннеля и закрывает права данных. Опция `--rotate-auth`
меняет ключ подписи и удаляет сессии, но сохраняет пароль администратора;
после неё нужно снова выполнить bootstrap для обновления publisher API-токена.

## Проверка и запуск

Сначала прогоните изолированные unit-тесты внутри уже собранного Pi-образа,
затем собирайте и поднимайте сервис. Образ называется строго
`claude-audiobook:latest`.

```bash
docker run --rm -v "$(pwd)/app:/app/app:ro" -v "$(pwd)/tests:/app/tests:ro" \
  claude-audiobook:latest python -m unittest discover -s tests -v

docker compose build
docker compose up -d
docker compose logs -f
```

`docker-compose.yml` сохраняет `build.network: host`: это обход DNS-проблемы
BuildKit на Pi, его не следует убирать. После запуска проверьте `/library`,
загрузите небольшую книгу и убедитесь, что сообщение Telegram содержит URL
`<public_url>/item/...` только после появления книги в ABS.

Без отправки в Telegram и без записи в рабочую библиотеку можно проверить
настоящий Silero и ffmpeg с временной EPUB-книгой:

```bash
docker run --rm --network none --cpus 2 --memory 3g \
  -v "$(pwd)/data/voices:/voice-cache:ro" \
  claude-audiobook:latest python -m scripts.smoke_offline --voices /voice-cache
```

Тест использует отдельное временное состояние, проверяет один M4B, две главы,
AAC mono 48 кГц и отсутствие пропущенных фрагментов. После завершения удаляет
только собственные временные результаты.

## Данные

```text
data/
  books/       вход из папки-наблюдателя
  work/<id>/   исходник, очищенный текст, план, manifest/WAV и publication.json
  audiobook/   собранный M4B до публикации
  library/     опубликованная структура Audiobookshelf
  abs/         конфигурация и метаданные Audiobookshelf
  abs-admin/   credentials.json, доступен только bootstrap-команде
  config/      приватная конфигурация и секреты
  cloudflared/ отдельный токен туннеля
  voices/      модель Silero
  state/       jobs.db
  backups/     резервные копии, создаются оператором
```

Промежуточные WAV удаляются после успешной сборки M4B, независимо от
доступности Audiobookshelf. Сам M4B, текст, план и метаданные задачи сохраняются
для повторной публикации и диагностики.
